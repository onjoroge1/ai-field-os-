# PR28 — Operations visibility

The owner Plan & usage screen includes the last 60 minutes of measured operations, failures, approximate p95 latency, feature activity, AI token cost estimates, unpriced AI requests and durable job health. Native tenant authorization protects dashboard and alert records. Empty windows show unknown latency rather than zero. Latency buckets are 50/100/250/500/1000/2000/5000/15000/60000 ms plus overflow. Request and worker/model spans are all measured operations; this is not a count of unique customer actions or a web-only SLO.

Field OS request IDs are generated on the server and returned in `X-Field-OS-Request-ID`. Background jobs retain the submitting trace ID; spans carry unique IDs and the job reference. JSON records go to the Frappe `field_os` site logger. Only a fixed field allowlist is emitted: operation category, tenant, trace/span/parent IDs, elapsed time, outcome and optional cost estimate. Never log prompts, message bodies, credentials, attachments, URLs, raw exceptions or payment payloads. Central collection is a deployment task: ship this log with the existing collector, restrict access to operations staff, use encrypted transport and apply a 30-day operational retention policy. No external log vendor or alert recipient is configured by this PR.

Redis holds per-tenant minute aggregates for two hours; the dashboard reads the last 60 buckets. Records survive application SQL rollback. Telemetry failures cannot turn a successful customer action into a failed response. Missing telemetry therefore requires an external heartbeat monitor for the collector, Redis and scheduler; a cache outage fails the dashboard visibly. The usage/billing ledger is authoritative and durable independently of telemetry.

Providers can return `ModelReply(model=..., input_tokens=..., output_tokens=...)`. Configure `FIELD_OS_MODEL_PRICES_USD_JSON` with an explicit model-to-rate map, e.g. `{"your-model":{"input":2,"output":8}}`, in USD per million tokens. Estimates cover the reported input/output counts; cached tokens, provider adjustments and other fees require provider billing reconciliation. Missing counts/rates remain unpriced. No live model pricing is invented or treated as a charge.

Every 15 minutes, durable alert records open or resolve for >=5% failed measured operations (minimum 20), p95 >2s (minimum 20), due jobs waiting >5 minutes, dead jobs, or ambiguous delivery. Current conditions also compute on dashboard read. Poll/service spans and job failures expose integration health. Operators inspect the trace and job, follow PR27 reconciliation, and check provider status. Configure external paging destinations and verify delivery before production; this change creates local alerts only. Thresholds are pilot defaults, not contractual SLOs.

Validation: pure tests cover cardinality, missing prices and percentile overflow; native Redis tests verify rollback-independent counters and tenant isolation. The owner browser check waits for the rendered operations screen. No external collector/page delivery or production load test has been performed.
